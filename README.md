# Kyuri Park — Portfolio

A static site: plain HTML, CSS, and a little JavaScript, generated by one Python script.
Nothing to install. macOS already has Python 3.

## Run it locally

```
python3 build.py serve
```

Open the address it prints (usually http://localhost:8000; if that port is busy it picks the next free one).
Edit any file in `content/`, `templates/`, or `assets/`, save, and refresh the browser.
If something in the JSON is broken, the browser shows what and where. Ctrl+C stops the server.

`python3 build.py` (without `serve`) just builds the site into `dist/`.

If you change `build.py` itself, stop the server (Ctrl+C) and start it again.

## Pages

| Address | What it is |
| --- | --- |
| `/` | Home: one card per featured project on an endless loop, filling the screen. The first time it opens in a tab, About's first sentence opens it, then gives way to the work (see Motion, "Home intro"). Home answers "who, and what matters most" |
| `/work/` | Work: everything, the projects first, in one grid of tiles. Its filters ("All 08   Digital 06   Brand 04   Physical 02", `/work/#digital` and so on) are off since 2026-11-09: `WORK_FILTERS` in `build.py` brings them back. Work answers "what else" |
| `/work/<slug>/` | One page per project, all built from `templates/project.html` |
| `/archive/` | Archive: personal work and hobbies, a gallery of images with nothing under them. A separate page with its own data |
| `/about/` | Read like a project page: one sentence at the top left, where a project's title is, the About text under it, then the photo edge to edge (gray until it exists), Experience, and a Contact label over the footer (`/about/#contact`) |
| `/contact/` | Not a page: it sends visitors straight on to `/about/#contact` (old links keep working) |

Contact is not a menu item: the links (email, LinkedIn, GitHub, Resume) are in the footer, one
line under a rule, with the copyright at the right, the same on every page except Home, which
has no footer (`templates/footer.html`, `.site-footer` in `assets/css/style.css`). On a phone the
links wrap onto a second line where they must, with no dots between them, and the copyright
takes the next line. On About a Contact label sits just over the footer, so the footer reads as
its list, and `/about/#contact` goes there (until 2026-11-06 About had a Contact section listing
the links one under another, and its footer showed only the copyright). They come from
`"email"`, `"linkedin"`, `"github"`, and `"resume"` in `content/site.json`.

## Edit text

- Anything written as `[PLACEHOLDER ...]` shows with a gray highlight on the page, and the build
  prints how many are left on each page.
- To link words inside a paragraph: `[typelab.ink](https://typelab.ink)`.
- JSON is strict: every item except the last in a list needs a comma, and text goes in "double quotes".

## Add a project

1. In `content/projects.json`, copy an existing project (from its `{` to its matching `}`) and paste it
   anywhere. `order` sets where it shows, everywhere: the home cards, the Work cards, and
   Previous / Next (which loop around at the ends). The counts on Work's toggle (when it's on) update on their own.
   To show it on Home too, give it `"featured": true`.
2. Give it a new `slug`: lowercase letters, numbers, and hyphens. Its page will be `/work/<slug>/`.
3. Create the folder `assets/images/<slug>/`.
4. Fill in the fields:

| Field | Where it shows |
| --- | --- |
| `order` | Required. A number; lower shows first. Work shows its cards in this order (within each filter, when they're on) |
| `category` | Required. A list of the Work filters it shows under, one or more of `"digital"`, `"brand"`, `"physical"`, like `["digital", "brand"]`. It counts under each, and once under All. The filters are off since 2026-11-09 (`WORK_FILTERS` in `build.py`), so it shows nowhere for now, but keep it filled in. ("Category" on the project page until 2026-11-09) |
| `featured` | Optional. `true` puts it on Home (aim for 3 to 5). Leave it out or set `false` and it's on Work only. Needs a `slug`, because a Home card opens the project's page |
| `title` | Everywhere |
| `oneLiner` | Under the home loop when that project is in the middle (3 words max); also the page's description for search engines and link previews. Not on Work (after the title in its Work card's caption until 2026-11-07) |
| `type` | Like "Font design tool". Not shown for a project (on its Work card until 2026-11-05, "Type" on its page until 2026-11-06); an item with no page shows it in the lightbox (after the title in its Work card's caption too, until 2026-11-07) |
| `roles` | Optional. A list, like `["UX research", "Art direction"]`. "Role" in the project page's facts, Role · Team · Timeline, what a recruiter reads a project's page for (since 2026-11-09; Category · Role · Year before). (Service in its place for a day, 2026-11-05) |
| `team` | Optional. Who you worked with, like `"2 designers, 3 engineers, 1 PM"` or `"Solo"` (or a list). "Team" in the facts |
| `timeline` | Optional. How long and when, like `"8 weeks, 2026"`. "Timeline" in the facts. (A project's `year` until 2026-11-09; the build reminds you if one is left. An item with no page keeps `year`) |
| `statement` | The one big sentence right under the project's title, in the lead style (leave it out to hide it) |
| `cover` | Home card and Work card |
| `todo` | Optional. A note to yourself, like `"confirm category"`; the build prints it every time until you delete it. JSON has no comments, so this does that job |
| `meta.link` | `{ "label": "typelab.ink", "url": "https://typelab.ink" }`, or `null` to hide it. Shows once, as "Visit typelab.ink ↗" in the body text under the statement, so type the label as the address reads (until 2026-11-06 also as "Link" in the metadata row) |
| `hero` | The large image or video at the top of the project page (same format as a block below) |
| `blocks` | Everything after the hero, in order |

Empty metadata fields are left out of the row.

### Block types

Blocks appear in the order you list them. The template uses Context → Explore (with a
"What broke" note) → Build → Result → Reflection. A `text` block with a `heading` starts a new section.

```json
{ "type": "text", "heading": "Context", "body": ["First paragraph.", "Second paragraph."] }

{ "type": "text", "heading": "What broke", "variant": "note", "body": ["A smaller aside."] }

{ "type": "image", "src": "context.webp", "alt": "What the image shows", "caption": "Optional" }

{ "type": "imagePair", "images": [
    { "src": "explore-1.webp", "alt": "..." },
    { "src": "explore-2.webp", "alt": "..." }
  ], "caption": "Optional" }

{ "type": "video", "src": "demo.mp4", "poster": "demo-poster.webp", "alt": "What the video shows" }

{ "type": "video", "src": "loop.mp4", "loop": true, "alt": "..." }

{ "type": "video", "embed": "https://www.youtube.com/watch?v=...", "alt": "..." }

{ "type": "impact", "items": [
    { "value": 1250, "suffix": "+", "label": "What the number counts" },
    { "value": 4.5, "prefix": "$", "label": "..." }
  ] }

{ "type": "prototype", "src": "assets/prototypes/light-life", "title": "Light Life app prototype" }
```

- `"loop": true` plays the video muted on repeat while it's on screen, like a GIF.
  Visitors with reduced motion turned on get a normal player instead.
- `embed` accepts YouTube or Vimeo links.
- **Impact numbers** count up when they scroll into view. Use only real, verifiable numbers.
  A `value` that isn't a plain number (empty, `[PLACEHOLDER]`, "TBD") is left out, and if no numbers
  are left the whole block disappears, so it's safe to leave a draft in place. No project has one yet.
- **Prototype** shows a working prototype that visitors can use, in a phone-sized frame on a
  gray stage, with an "Open in a new tab" link under it (on a phone, that fills the screen).
  `src` is a folder with its own `index.html`. The page inside draws itself at 390 × 844 and
  scales to the frame. Light Life's app lives in `assets/prototypes/light-life/`
  (`index.html`, `app.css`, `app.js`, no libraries, using the site's fonts). `sky.js` plans
  the light around where the visitor lives: sunrise and sunset worked out in the browser, the
  weather and the city search from Open-Meteo (free, no key; credited in the app), the first
  city guessed from the computer's time zone, and a recommended scene per part of the day,
  with its one-sentence reason (`recommend()`, the rules and the words). It is built on
  the Light Life design system (https://claude.ai/artifact/EM7wMb1WZ6GntbUNgzRzLW, private):
  `app.css` copies its Night tokens and `ll-` components, so change a value there first.

## Items with no page

An item in `content/projects.json` with no `slug` has no page of its own and isn't on Home. On
Work it's a tile like any other, with "Type · Year" at the right of its title. Clicking it opens its images
larger in a lightbox (Esc, Close, or a click outside the image closes it; ← and → step through the
items of this kind that the filter is showing). Its images go in `assets/images/pieces/`:

```json
{
  "order": 7,
  "category": ["brand"],
  "title": "Editorial Projects",
  "type": "Editorial",
  "year": "2025",
  "images": ["editorial-1.webp", "editorial-2.webp"],
  "alt": "What the images show"
}
```

- **Add one:** copy an item (from its `{` to its matching `}`), paste it anywhere, and fill it in.
  The counts on the toggle update on their own.
- **Reorder:** change `order`. That sets its place in the grid and for ← / →.
- **Remove:** delete the item.
- **Give it a page:** add a `slug` and the project fields from "Add a project".
- **Images:** the first one is the thumbnail. The lightbox shows all of them, one under the other.
  `alt` describes them for screen readers; with several images, each gets "(1 of 3)" and so on added.

## Archive

`/archive/` is built from `content/archive.json`, separate from the projects. Each entry is one
image; the page shows them in the file's order, with nothing under them:

```json
{ "id": "009", "src": "009.jpg", "caption": "Sketchbook study", "date": "2025-08", "alt": "What the image shows" }
```

| Field | Where it shows |
| --- | --- |
| `id` | Required. A number in quotes (`"009"`), not shown on the page; screen readers announce it as "Image 009". Each one has to be different |
| `src` | Required. A file in `assets/images/archive/`. Each entry needs its own file name (not `009.jpg` and `009.webp`) |
| `caption` | Optional. Only in the lightbox, on one line with the date; a caption too long for the screen is cut short with "…" (the date never is). Leave it `""` to show nothing |
| `date` | Optional. Shown as you write it |
| `alt` | What the image shows, for screen readers. The build reminds you if a real image has none |

- **Add an image:** save it in `assets/images/archive/` and add an entry. Any shape works: images
  are never cropped, and their size is read from the file.
- **Swap a gray box:** save your image under the name in its `src` (`001.jpg`, and so on). To use
  another format, like `.webp`, change `src` too. Until the file exists, an entry shows as a gray
  box, in eight shapes in turn (`ARCHIVE_BOXES` in `build.py`).
- **Reorder:** move the entries in the file. Columns fill from top to bottom, so 001, 002, and so
  on run down the first column, then the second.
- **Remove:** delete the entry.
- **Faster grid (optional):** the grid shows each image at a quarter to half of the page's
  width, so a smaller copy saves a lot of loading, most of all on phones. Run
  `python3 build.py images` (see "Smaller copies for phones" below), or save one by hand at
  about 800 px on the long side next to the full one, with `-small` before the ending
  (`009-small.jpg` for `009.jpg`). The grid then uses it where it's enough, and the lightbox
  always shows the full image. Leave `src` as it is.

Clicking an image opens it large: Esc, Close, or a click outside the image closes it, and ← and →
step through the images. The gallery is 2 columns on phones, 3 from 768px, 4 from 1200px. Without
JavaScript, an image opens on its own instead, and the caption and date show under it.

## Swap in real images and videos

Every gray placeholder shows the project name and the filename it's waiting for (for example
`hero.webp`), except on Home, where a card without its cover is a plain gray block, and About's photo, which is plain gray too. Save your image with that name in that project's folder, refresh, and it replaces the
placeholder. To use a different name or format, change `src` in `projects.json`.

Recommended exports (WebP, or AVIF; JPG and PNG work too):

| Slot | Size | Notes |
| --- | --- | --- |
| Cover (Home cards and Work tiles) | 1600 × 2000 | 4:5 on Home and Work, one file for both (`--thumb-ratio` in `assets/css/style.css`; 1:1 on 2026-11-06, 3:4 on Home before that). Another shape is cropped to fill the 4:5 frame, so keep the subject near the middle |
| Hero and full-width | 2400 px wide | Any height; the hero runs edge to edge |
| Two-image row | 1200 px wide each | Same ratio for both looks best |
| About photo | 2400 × 1600 | Runs edge to edge under the About text at 3:2, as a project's hero does (up to 1920px wide). Until it exists its place is plain gray, with no label |
| Image of an item with no page | 1200 × 1500 | The same 4:5 as a cover, so the Work tile shows all of it; another shape is cropped to fill the tile. The lightbox shows the whole image |
| Archive image | 1500 px on the long side | Any shape; never cropped |

Aim for under ~500 KB per image. [Squoosh](https://squoosh.app) or Figma's export both make WebP.
Width and height are read from the file automatically, so the page doesn't jump while loading,
and images further down the page load only when they're about to be seen.

**Smaller copies for phones:** after adding images, run `python3 build.py images`. It saves a
smaller copy next to each large image that has none yet (`cover-small.jpg` next to
`cover.webp`: 1200 px wide, or on Archive 800 px on the long side; a WebP or AVIF image's copy is
a JPG, since the Mac's built-in `sips`, which it uses, can't write those). Pages then load the
copy where it's enough (phones, mostly) and the full image where it isn't: Home's cards, Work's
tiles, project images, and Archive (the lightbox always shows the full image). Keep the copies
in the folders and push them with the rest; running it again only makes the missing ones. The
build reminds you while large images have no copy. Not on a Mac? Save the copies by hand under
those names. (Since 2026-11-09; Archive's only before.)

**Video on the Work tile:** put `cover.mp4` next to the cover image (same name, `.mp4`).
Hovering that project's tile on the Work page then plays it muted on a loop over the
image. Keep it short (3–8 s), silent, H.264, and under ~3 MB.

**Clack demo:** Clack's hero is a video slot labeled "Demo video" (`demo.mp4`, with an optional
`demo-poster.webp`). When the demo has a public address, add it as `meta.link`.

**Link previews (LinkedIn, Slack, iMessage):** a project uses its cover if the cover is a JPG or PNG.
Otherwise, and for the other pages, it uses `assets/images/og.png`.

**Resume:** replace `assets/Kyuri-Park-Resume.pdf`, keeping the same name.

**About's first sentence:** `"headline"` under `"about"` in `content/site.json`. Each string in
the list is one line from 768px up (on phones they run together and wrap evenly); type it in
capitals or not, it shows in capitals either way. It's the display style (Inter Display 500,
line-height 1, -0.04em; 41px, 51px from 1200px, 64px from 1440px: `--size-display`, and
`.about-headline` in `assets/css/style.css`), left-aligned on the header's left edge, and as
far down the page as Work's and Archive's images and a project's title start (`--grid-top`,
the height of Work's filter line and the space under it), so switching among them moves nothing. Delete
`"headline"` and About opens on the text instead.

**About's text and photo:** About is laid out as a project page is (since 2026-11-06). The About
text (`"paragraphs"`) is in the label style (Martian Mono, 12px, capitals, in the text color;
since 2026-11-07, the lead style for a day before; the body style for a few hours on 2026-11-09,
then back to the label at Kyuri's call), left-aligned, 32px under the sentence, as a
project's statement is under its title, with 24px between paragraphs. Then the photo
(`"portrait"` in `content/site.json`, `assets/images/about/portrait.webp`) runs edge to edge at
3:2, as a project's hero does, plain gray (`--color-fill`) until it exists; gray edge to edge
only ever stands for a picture, never behind text. Then Experience, and the Contact label over
the footer (`.about-hero`, `.about-text`, `.about-portrait`, `.about-contact` in
`assets/css/style.css`). The page scrolls as any other does. Until 2026-11-06 the sentence sat
alone, centered, in a window-tall first screen with "[ Scroll down ]" at its foot; the text sat
centered on a window-tall gray block; and the scroll was sticky, each block sliding over the one
before (snapping and whole-screen steps were tried on 2026-11-05 and taken out the same day).

## Header

The name ("Kyuri Park", from `content/site.json`, shown in capitals) is at the left, in the name
style like the links (Inter Display, 14px) and a weight heavier (`.identity` in `assets/css/style.css`), and Work, Archive,
and About at the right, on one line at every width (down to 320px), from `templates/base.html` on
every page. The current page's link is in the text color and the others are gray
(`--color-subtle`, the lightest gray that passes WCAG AA; a lighter `--color-faint` at 3:1, which
didn't, from 2026-11-05 to 2026-11-09) until hovered (`.site-menu a` in `assets/css/style.css`; see Type and color). On phones the links close up. If a visitor has set
larger text in their browser or phone and it still doesn't fit, the links move to a second line, at
the right.

The header is sticky: it stays at the top of the window while the page scrolls, with no
background, so the page scrolls under the name and links (`.site-header` in
`assets/css/style.css`). `/about/#contact` scrolls to About's Contact label, as far as the page
goes, kept clear of the header.

`<body data-page="…">` names the kind of page (`home`, `work`, `project`, `archive`, `about`,
`404`), for CSS that applies to one page only, like the space over About's footer.

## Type and color

Every size, line height, and color on the site is a token at the top of
`assets/css/style.css`; no rule sets its own. The type follows titarvl.framer.website/about
(since 2026-11-05): two typefaces, Inter Display (the Inter file's optical size at 32, set on
`body`) and Martian Mono, both self-hosted from Google Fonts under the SIL Open Font License, in
six styles. Each style is a typeface, a size, a line height, and a tracking, with tokens named
after it (`--size-name`, `--leading-name`, `--tracking-name`…), and each is set once, under
"Shared text styles". Four are titarvl's; "name" was added on the user's ask (2026-11-05), so the
menu bar and project names are a sans while the small labels stay in Martian Mono, and "lead" on
2026-11-06, so a project's statement reads as the step between its title and its text.

| Style | Type | Size | Line height, tracking | Used for |
| --- | --- | --- | --- | --- |
| display | Inter Display 500, capitals | 41px, 51px from 1200px, 64px from 1440px | 1, -0.04em | About's first sentence, project titles, the 404 (About's section headings too, until 2026-11-06) |
| title | Inter Display 500, capitals | 18px, 23px from 768px, 29px from 1200px, 36px from 1440px | 0.9, -0.01em | impact numbers, Previous / Next titles |
| lead | Inter Display 500, as typed | 20px, growing with the window to 28px (from 800 to 1120px wide); lines up to 30em (`--measure-lead`) | 1.35, 0 | a project's statement, under its title (About's text too, 2026-11-06 to 2026-11-07) |
| body | Inter Display 500, as typed | 16px | 1.5, 0 (1.1 from 2026-11-05 to 2026-11-09) | text, a project's "Visit" link; links in text at 600 (Contact's links and About's text too, until 2026-11-06) |
| name | Inter Display 500, capitals | 14px | 1.3, -0.01em | the menu bar (Work, Archive, About, the lightbox's Close; the name at 600, 16px and +0.02em, see below) and project names (Home's cards, Work's tiles, Archive, the lightbox) |
| label | Martian Mono 400, capitals | 12px | 1.3, -0.05em | Work's filters, Home's one-liners (in `--color-subtle`, `--color-muted` until 2026-11-07; on Work's tiles too, until the same day), captions, project facts, the footer, the lightbox's type and year, About's text (since 2026-11-07) and Experience; a label that names a column or a section (a project's fact labels, Role, Team, Timeline, its section and note headings, and About's Experience and Contact headings) looks as Work's filters do, in `--color-subtle` (at 600 in `--color-muted` until 2026-11-06) |

Two weights for Inter Display, 500 and 600, and one for Martian Mono, 400 (600 too until 2026-11-06). Two sizes
sit outside the styles: Work's counts, a label at `--size-count` (10px), and the name in the
header, 16px (`--size-identity`) at +0.02em (`--tracking-identity`), a step bigger and more open
than the links beside it (since 2026-11-05; at 14px and -0.01em like them it read weaker, its open
letters carrying less ink than theirs). Until 2026-11-05 the
type was Inter alone, at 400 and 500, with a 32-64px display, 28-48px titles, a 14px header, and
line height 1.5 for all text.

Color is the text color (`--color-text`), one gray for all gray text (`--color-subtle`, 4.6:1 on
the background, the lightest small text stays easy to read at: one-liners, Work's filters,
captions, the lightbox's type and year, the labels that name a column or a section, impact labels,
Previous / Next, About's Experience companies and dates, the copyright, and since 2026-11-09 the
header's links; since 2026-11-07, most of them a step darker in `--color-muted`, 5.6:1, before),
`--color-muted` now only for a hovered link, and `--color-line` for rules. (From 2026-11-05 to
2026-11-09 the header's links were lighter still, `--color-faint`, 3:1, under WCAG AA's 4.5:1.)
Things react to the pointer in one of two ways, and only by color:
**links** are in the text color and turn muted on hover (the name, links in text, the footer,
project links, the lightbox's buttons); **choices** are in a lighter gray and
turn to the text color when hovered or current (the header's links and Work's filters, in
`--color-subtle`). A link that opens a new tab (LinkedIn, GitHub, the résumé PDF, a project's "Visit" link: any
`target="_blank"`, which `build.py` sets on every external link and PDF) ends in a small ↗,
drawn by CSS in the link's color (since 2026-11-05). It hangs on the link's last word, so it never
wraps onto a line alone, and in Windows' contrast themes it takes the theme's link color.

**Capitals** come with every style but body and lead, so everything but text is in capitals:
titles, names, captions, and the footer too. Type them in sentence case in `content/` and the
templates; CSS sets the capitals. Body text and the lead stay as typed, and so does an email
address, even in the footer (in capitals it reads as a shout).

**Breakpoints** are 768px and 1200px, the same two on every page: under 768px is a phone. 1440px
steps up the display and title sizes only, as titarvl's do. Work's grid alone goes by 640px and
1440px: 1 column under 640px, 2 from 640px, 3 from 1440px (since 2026-11-06).

## Spacing

Three values at the top of `assets/css/style.css` set the spacing around the work on every page:
`--space-1` (16px, image to caption, for every caption on the site), `--space-2` (32px, filter or title to the grid), and
`--space-3` (the header's text to the page's first thing: 96px on phones, 128px from 768px).
`--page-top` turns that into
where every page starts: `main` has it as `padding-top`, so Home's middle card, Work's filter,
and the 404 all start on the same line (104px under the header's box from 768px, 80px on
phones). `--grid-top` (Work's filter line and `--space-2` under it, 48px) sets where Work's
images start under that line, and Archive's images, a project's title, and About's first
sentence start there too (since 2026-11-06), so going from Work to any of them, or among them,
moves nothing. For the two titles it's their capitals' top that sits on that line, not the top
of their line, which is higher by the room over the capitals (`--cap-display`, 0.13em: 8px at
64px, 5px on phones), so a title doesn't look lower than an image beside it in the menu. Over the
header's text is `--header-top` (16px from 768px, 12px on phones). To move
that line, change `--page-top` (or `--space-3`) at the top of `assets/css/style.css`; nothing on
a page adds its own space over its first thing. `--gutter` is the side margin the
header and the page share, so their edges line up: 16px on phones, 24px from 768px, 32px from
1200px. `--page-max` (1600px) is the widest the page and the header run; past it, both stay
centered with the same edges. `--media-gap` (12px) is the space between images on every page
and screen: Work's columns, Archive's images across and down, Home's cards, images side by side or
one under another on project pages, and in the lightbox. `--step-1` and up are 8px steps, for the
spacing inside things (`--step-3` is 24px).

## Motion

The site keeps motion to a short list: the home loop and its intro, About's first sentence breaking into dots under the pointer, the Work toggle's fade, the Work and Archive images growing slightly (3%) and Work's videos playing on hover, images
fading up on project pages, a 300 ms fade between pages (in browsers that support it; others switch pages instantly), the lightbox fading in and out (200 ms), impact numbers counting up, and a smooth scroll to a spot on a page (`/about/#contact`). If a visitor has reduced
motion turned on, all of it is off, and the home loop jumps from card to card without easing.

Home loop: the home page shows the featured projects, fills the screen, and doesn't scroll; after the last project comes the first again, both
ways. Mouse wheel or trackpad (down/right = next), drag, swipe, and the
left/right arrow keys all move it; after a short pause it settles with one card in the middle,
its title and one-liner under it (title at the card's left edge, one-liner at its right as a gray mono label, so the two don't read as one line). Click the middle card to open it; click a side card to bring it to the middle.
Tab moves through the cards, bringing each to the middle. Without JavaScript, the home page is a
plain list of the projects.
On a phone the cards beside the middle one are off screen, so two things say there are more
(since 2026-11-09): a dot for each project 16px under the caption, the middle card's dark (4px
dots, 8px apart, `.track-dots` in `assets/css/style.css`; none from 768px, where the neighbors
show), and, once a visit, as the page shows (after the opening, when it plays), the row leans
toward the next card and back (`LEAN`, `LEAN_HOLD`, `LEAN_DELAY` at the top of
`assets/js/track.js`). Not if the row has been moved first, or with reduced motion.

To tune it:
- `assets/js/track.js`, at the top: `WHEEL_SPEED` (cards per pixel of wheel/trackpad scroll),
  `WHEEL_MAX` (the most one wheel event can count for, which tames trackpad flicks),
  `SETTLE_DELAY` (ms of no input before it settles), `EASE` (how quickly it glides),
  `TICK_VOLUME` (the soft tick each time a new card reaches the middle, 0 to 1; 0 turns it off,
  and it's 0 since 2026-11-09, since a visitor may be in an office or on a call; 0.3 before),
  `TICK_TONE` (its pitch in Hz; higher sounds brighter). The tick is made in the browser, no
  sound file, and stays silent until the visitor has clicked, tapped, or pressed a key on the page.
- `assets/css/style.css`: `--thumb-ratio` at the top (the cards' shape, width / height, `4 / 5`;
  Work's tiles use it too). "Home: project track": `--card-gap` (space between cards: `--media-gap`,
  12px, as between images on every page), `--card-share` (the middle card's least height as a share
  of the window's, `62dvh` from 768px: 558px on a 900px-tall window; under 768px the whole stage,
  so a phone's card runs between the side margins whenever the height allows; on taller windows the card grows so the
  space under its caption is no more than the space over it, and on a window too narrow for that,
  the card moves down to even them out), `--card-w`, `--card-h` (on phones and narrow windows the
  card runs between the side margins, `--gutter`, lined up with the header), `--peek-min` (the
  least of a neighbor card worth showing, 48px: when less would show, it starts just off screen
  instead of as a thin strip at the edge),
  `--room-bottom` (the least under it, room for a caption of up to two lines; on short screens the
  card shrinks to keep this), `--scale-1` (card size one step from the
  middle), `--scale-2` (two steps or more), `--opacity-1` / `--grayscale-1` / `--brightness-1`
  (cards one step from the middle and beyond: full opacity, grey, a little darker),
  `--fade-step` (each further step multiplies the opacity by this), `--blur-step` (and adds
  this much blur).

it), `DOT` (a dot's width, in cells), `REACH` (how far the pointer reaches, in the sentence's
font size), `PUSH` (how hard it pushes), `SPRING` / `DRAG` (how the dots hold and slow down near
the pointer), `RETURN` (how fast they go home once it has passed), `SWEEP` / `WAKE` (how much

only the ones under the frames' positions); for the pass on arriving, `PASS_SPEED` (px per ms, on average), `PASS_TIME` (ms at the

smaller cuts a single line more nearly through the middle) and `PASS_BOW` (how far it bows up). The
dots take the sentence's color, the patches the background behind it (a part with its own, like
a `[PLACEHOLDER]`'s highlight or a link in another color, keeps its own).

## Deploy

The site is hosted on Netlify. Push this folder to GitHub (`dist/` is ignored; Netlify builds it).
On Netlify: Add new site → Import an existing project → pick the repo. `netlify.toml` already sets
the build command (`python3 build.py`) and the output folder (`dist`).
No Git? Run `python3 build.py` and drag the `dist` folder onto https://app.netlify.com/drop.

Link previews (LinkedIn, Slack, iMessage) and the sitemap need the site's full address. When
Netlify builds the site from Git, the build takes it from Netlify (its main address: the
`.netlify.app` one, or your own domain once it's set), so there's nothing to do (since
2026-11-09). For a drag-and-drop deploy or another host, put the address in `"siteUrl"` in
`content/site.json` (for example `"https://kyuripark.com"`); `"siteUrl"` always wins when it's
set. `python3 build.py serve` uses the local address (http://localhost:...) in its place, and a
build with no address leaves those full-address tags and the sitemap out.
Custom domains are set up in Netlify's domain settings.

The build also writes `robots.txt` (search engines welcome) and, with the address,
`sitemap.xml`, listing Home, Work, each project, Archive, and About (since 2026-11-09).
